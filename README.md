# TechCompass

**新技术与我正在做的项目，到底有什么关系？**

TechCompass 是面向 AI Agent 用户的 Windows 桌面技术相关性助手。输入一个技术名词、一条 GitHub 链接或一张截图，它会结合已关联项目的目标、技术栈和当前阶段，解释技术用途，并帮助你决定：**现在看、以后看，还是可以忽略。**

它不是另一部 AI 百科，也不鼓励你学会每一个新工具。它希望让一次技术探索，回到你真正想完成的事情上。

## 为什么做这个产品

当你用 Codex、Claude Code 等工具推进项目时，往往还会不断看到新模型、新框架和开源仓库。理解“它是什么”只是第一步，更难的问题是：

- 它能解决我当前的具体问题吗？
- 它会替代现有工具，还是只是补充一个能力？
- 接入和学习的成本，值得现在承担吗？
- 如果暂时不用，什么情况下值得重新看？

通用问答需要反复补充背景，收藏夹则容易成为另一份待办清单。TechCompass 把项目上下文带进判断里，让“现在不用学”也成为一个有依据的答案。

## 谁适合使用

正在用 AI 辅助推进真实项目的独立开发者、产品设计师和创作者，尤其适合同时关注多个项目、希望减少技术探索打断的人。

首版以已有本地项目目录的用户为主；如果只是查询术语、不需要结合项目做决定，普通问答工具可能更直接。

## 一次分析能得到什么

| 内容 | 回答的问题 |
| --- | --- |
| 核心词与简短解释 | 它是什么，主要解决什么问题？ |
| 逐项目相关度 | 与哪个项目相关，依据是什么？ |
| 当前投入建议 | 现在看、以后看，还是可以忽略？ |
| 替代或补充的位置 | 能放进现有流程的哪一部分，接入成本是什么？ |
| 验证动作或未来条件 | 现在怎么小规模试，或等什么需求出现后再看？ |
| 检索来源与待确认项 | 判断参考了哪些材料，还有哪些信息不确定？ |

**相关度与采用时机分开判断。** 一项技术即使高度相关，也可能因为项目临近交付、迁移成本较高或缺少实际需求而被建议延后。

例如，一个正在交付的 Electron 原型遇到新的桌面框架：合理的建议可能是先完成当前版本，等包体积或资源占用成为真实问题时，再做一个页面的迁移实验，而不是立即重写。此例用于解释产品思路，并非固定的模型输出。

## 下载与开始使用

1. 下载 [TechCompass 0.3.2 Windows ZIP](https://github.com/fishwithoctopus/TechCompass/releases/download/v0.3.2/TechCompass-0.3.2-Windows.zip)。
2. 将整个压缩包解压到一个固定目录，然后打开其中的 `TechCompass.exe`。不要只移动 EXE，运行时需要同目录下的配套文件。
3. 在项目管理中关联一个真实项目目录，查看并纠正提炼出来的目标、阶段、技术栈和当前任务。
4. 返回分析页，选择可用引擎，输入技术词、链接或图片，再点击“分析”。
5. 阅读逐项目建议，并按需展开判断依据与来源。项目重点变化后，请刷新或纠正上下文。

这是 **Windows x64 便携版**，不是新的 Setup 安装器。首版没有提供 macOS、Linux 或手机版本，也未新增代码签名；请按你所在设备或组织的安全政策决定是否运行，不要为运行程序关闭安全防护。

### 图片与桌面操作

- 图片支持“选择图片”、拖入和粘贴，提供预览与移除。
- 支持 PNG、JPEG、WebP、GIF，单张最大 8 MB。
- 卡片可以收起；`Ctrl + Shift + T` 可切换显示状态。
- 程序会驻留托盘，需要完全退出时，在托盘菜单中选择“退出”。

## 模型和联网要求

TechCompass 不内置一个永久免费模型。真实分析会使用你选择的服务与对应额度。

| 分析方式 | 使用前提 | 当前联网方式 |
| --- | --- | --- |
| 本机 Codex | 已安装可用 CLI、完成登录且有额度 | 技术词和截图可走一次调用中的检索与项目判断 |
| 本机 Claude Code | 已安装可用 CLI、完成登录且有额度 | 当前技术词检索先借助 Codex，再交给分析模型 |
| 自定义 API | 在设置中填写兼容接口地址、模型名和 API Key | API 分析不自动等于联网；当前技术词检索仍依赖 Codex |
| 演示引擎 | 用户主动选择 | 预设模拟，不代表真实联网结果 |

直接链接会尝试读取原文；网页登录限制、访问权限或站点结构可能导致读取失败。输入只有短词且存在同名对象时，产品可能先列出技术候选，再请你补充信息。

真实引擎不可用或调用失败时，应明确提示错误，**不会悄悄用演示结果冒充真实分析**。不确定选择哪个引擎时，可先明确选择已登录的 Codex 验证链路。

### 为什么分析仍可能需要几十秒

一次完整分析包含联网查找、资料识别和项目判断。0.3.2 将 Codex 路径从两段调用合并为一次；一次实际对比约从 **52 秒缩短到 31 秒**。这是单次观测，不是平均值或性能承诺，耗时仍受网络、模型负载和对象歧义影响。

短期内相同输入与项目上下文可使用缓存。项目发生变化时，应刷新理解，避免依赖过期结果。

## 与 Agent 如何配合

产品有两个入口：

- **桌面卡片给人使用**：输入材料、看分析、管理项目与历史。
- **MCP 接口给 Agent 使用**：在工作会话中传递项目摘要和结果，与本地核心共享记录。

桌面分析可以启动本机 CLI，不要求你先打开一个 Agent 对话窗口，但仍需要工具已安装并完成登录。

MCP 接入不是“安装后自动读取所有项目”。项目需要明确关联或由 Agent 提交摘要；不同宿主的注册方式与权限不同。首版不宣称兼容所有 Agent，也不承诺后台持续同步所有项目。

## 数据与隐私

- 项目记录和分析历史保存在本机，默认目录为用户目录下的 `.techcompass`。
- **本地保存不等于离线分析**：输入内容和必要的项目上下文会发送给你所选的模型服务，请勿提交不允许外传的资料。
- 联网提示词要求只用公开技术关键词检索，不把项目私密信息放入搜索查询；这是模型行为约束，不是独立的网络隔离保证。
- Windows 桌面版在系统加密能力可用时加密保存 API Key。账号登录信息和本机项目数据没有随此发布包分发。
- 不监听剪贴板、不自动监控浏览活动、不默认扫描整个磁盘；项目背景由用户明确关联。
- 0.3.2 已移除反馈界面。保存历史记录不代表训练模型，也不应被理解为产品会自主持续学习。

## 当前验证与已知限制

已完成的验证包括：

- 81 项自动化测试，涉及配置处理、存储、分析管线、HTTP、MCP 协议与搜索约束等。
- 真实 Codex 联网分析、来源保存与逐项目判断。
- 桌面图片选择、预览、移除及结果页交互走查。

这些结果不代表所有机器、所有模型或所有 Agent 的完整兼容验收。尤其需要注意：

- 模型仍可能误解资料或给出不准确建议，重要决定请核对原始来源。
- 项目上下文可能过期，代码也不能完全表达你的真实目标。
- 图片识别质量取决于所选模型；自定义 API 未对所有供应商做完端到端验证。
- 建议仅用于辅助判断，不会替你安装依赖、迁移代码或执行采纳动作。
- 当前仍是原型，尚未通过正式用户研究证明能改善焦虑或提高生产效率。

遇到问题时，可通过本仓库 [Issues](https://github.com/fishwithoctopus/TechCompass/issues) 描述复现步骤、版本和所选引擎。提交日志或截图前，请遮盖 API Key、令牌、私有代码和个人路径等敏感内容。

本仓库提供可运行版本的备用下载入口，便于查看和验证，不代表 GitHub 链接必然能替代招聘方要求的 REDcowork 作品链接。平台作品的最终提交方式以招聘方要求为准。

界面使用 Lucide 图标，相关 ISC / MIT 许可文件随应用保留。第三方运行时及依赖适用各自的许可证。
